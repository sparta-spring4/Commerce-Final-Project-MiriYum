# MiriYum 일반 사용자 화면 디자인 상세 지시서

> **문서 지위:** 이 문서는 프론트 작업을 위한 비정본 인계 자료다. 제품·정책·아키텍처·API 사실은 이 문서가 소유하지 않는다. 충돌하거나 구현 시점이 달라졌다면 [`AGENTS.md`](../../AGENTS.md), [`ai/document-routing.md`](../../ai/document-routing.md), [`docs/00-index.md`](../../docs/00-index.md), 활성 [`service-policies`](../../docs/service-policies/README.md), 도메인별 `spec.md`·`openapi.yaml`, 실제 Controller·테스트 순으로 다시 확인한다.

> **직접 대조:** [`ownership.md`](../../docs/specs/mvp1-common/ownership.md), [`auth-account/openapi.yaml`](../../docs/specs/auth-account/openapi.yaml), [`store-search/openapi.yaml`](../../docs/specs/store-search/openapi.yaml), [`reservation/openapi.yaml`](../../docs/specs/reservation/openapi.yaml), [`menu-hold-pickup/openapi.yaml`](../../docs/specs/menu-hold-pickup/openapi.yaml), 실제 [`ConsumerAuthController`](../../backend/src/main/java/com/miriyum/domain/consumer/controller/ConsumerAuthController.java)·[`StoreSearchController`](../../backend/src/main/java/com/miriyum/domain/store/search/controller/StoreSearchController.java)·[`ReservationController`](../../backend/src/main/java/com/miriyum/domain/reservation/controller/ReservationController.java)·[`MenuHoldAvailabilityController`](../../backend/src/main/java/com/miriyum/domain/menuhold/controller/MenuHoldAvailabilityController.java)·[`PickupReservationController`](../../backend/src/main/java/com/miriyum/domain/pickup/controller/PickupReservationController.java)를 기준으로 한다.

## 문서 사용법

이 문서는 저장소에 접근할 수 없는 디자인 AI에게 그대로 전달한다. 화면을 임의로 합치거나 기능을 생략하지 말고, 각 화면의 기본·로딩·빈 상태·오류·완료 상태를 함께 디자인한다. 사용자 화면에 `1차 MVP`, `2차 MVP`, `고도화`라는 개발 용어는 표시하지 않는다.

단계 표시는 산출물 관리용이다. 1차 MVP만 노출해도 탐색→예약 또는 탐색→픽업 흐름이 완결되어야 하며, 미래 기능을 숨겼을 때 빈 탭·빈 카드·막힌 버튼이 남으면 안 된다.

## 공통 화면 구조

반드시 포함할 공통 요소:

- MiriYum 로고와 일반 사용자 서비스임을 알 수 있는 헤더
- 데스크톱: 상단 내비게이션, 모바일: 하단 내비게이션
- 핵심 메뉴: 매장 찾기, 내 예약, 마이페이지
- 로그인 전·후 헤더 변형
- 로딩 스켈레톤, 결과 없음, 네트워크 오류, 재시도
- 색상 외에 텍스트·아이콘·형태를 함께 사용한 상태 표시
- 키보드 탐색, 명확한 포커스, 입력란 라벨, 오류 설명

포함하지 않을 공통 요소:

- 매장 관리, 플랫폼 관리 메뉴
- 구현되지 않은 기능의 `준비 중` 버튼
- 고객에게 내부 enum·오류 코드·MVP 단계명 노출

## 1차 MVP 화면

### 1. 일반 사용자 회원가입 화면

#### 화면 목적

일반 사용자 계정을 생성하는 화면이다. 식당 대표자 회원가입과 명확히 구분한다.

#### 반드시 포함할 요소

- MiriYum 로고, `회원가입` 제목
- 이메일 입력 및 이메일 확인 완료 상태
- 휴대전화 본인확인 완료 상태
- 닉네임, 비밀번호, 비밀번호 확인
- 비밀번호 표시·숨김
- 만 14세 이상 확인 안내
- 약관·개인정보처리방침 링크
- 가입 버튼, 로그인 이동 링크
- 고객용 계정이라는 안내와 식당 대표자 서비스 이동 링크

#### 입력란

- 이메일: `user@example.com`, 빈값·형식·중복 오류
- 닉네임: 2~20자 안내, 사용 불가 문자·예약어 오류
- 비밀번호/확인: 일치 여부와 안전 조건 표시
- 이메일 확인 및 본인확인: 완료·만료·다시 확인 상태

#### 화면 상태와 문구

- 기본, 입력 중, 필수 누락, 이메일 중복, 확인 미완료·만료, 처리 중, 가입 성공, 네트워크 오류
- 중복: `이미 사용 중인 이메일입니다.`
- 확인 만료: `확인 시간이 만료되었습니다. 다시 확인해 주세요.`
- 성공: `회원가입이 완료되었습니다. 로그인해 주세요.`

#### 성공 후 이동

로그인 화면으로 이동한다. 자동 로그인으로 처리하지 않는다.

#### 포함하지 않을 요소

카카오 등 소셜 가입, 프로필 이미지, 결제수단, 알레르기 정보, 사업자정보, 역할 선택.

#### 선택 요소

서비스 소개 이미지, 비밀번호 조건 체크리스트, 단계형 가입 레이아웃.

### 2. 일반 사용자 로그인 화면

#### 화면 목적

일반 사용자 계정으로 고객 서비스를 이용하기 위한 화면이다.

#### 반드시 포함할 요소

- 이메일, 비밀번호, 표시·숨김, 로그인 버튼
- 회원가입 이동, 식당 대표자 로그인 이동
- 실패 메시지 영역, 약관·개인정보처리방침
- Enter 로그인과 처리 중 중복 클릭 방지

#### 화면 상태와 문구

- 기본, 형식 오류, 필수 누락, 처리 중, 실패, 재시도 대기, 세션 만료
- 실패: `이메일 또는 비밀번호를 확인해 주세요.`
- 제한: `잠시 후 다시 시도해 주세요. 54초 후 재시도할 수 있습니다.`
- 만료: `로그인 시간이 만료되었습니다. 다시 로그인해 주세요.`

#### 성공 후 이동

원래 접근하려던 화면이 있으면 그곳으로, 없으면 매장 찾기로 이동한다.

#### 포함하지 않을 요소

1차 MVP에서는 소셜 로그인, 로그인 상태 유지, 휴대전화 로그인, 역할 선택, 관리자 로그인.

### 3. 매장 찾기·검색 결과 화면

#### 화면 목적

지역·카테고리·키워드와 완전한 예약 조건으로 매장을 찾는 핵심 화면이다. 비회원도 이용할 수 있다.

#### 반드시 포함할 요소

- 키워드 검색창: 매장명·메뉴명·지역명 검색 안내
- 지역 필터: 서울·부산·대구·대전·광주
- 매장 카테고리 필터, 예약 가능만 보기
- 선택형 예약 조건: 날짜·시작 시간·인원
- 검색·초기화, 적용 조건 칩, 결과 수, 정렬 기본값
- 매장 카드: 이름, 지역·주소, 카테고리, 태그, 운영 상태, 요청 조건의 예약 가능 여부
- 페이지 이동 또는 더 보기

#### 상호작용

- 예약 가능만 보기는 날짜·시간·인원이 모두 입력된 경우에만 활성화한다.
- 일부 조건만 입력하면 필요한 조건을 해당 영역에서 안내한다.
- 카드 선택 시 검색 조건을 유지한 채 매장 상세로 이동한다.

#### 화면 상태와 문구

- 첫 진입, 검색 중, 결과 있음, 결과 없음, 조건 오류, 서버 오류
- 조건 없음: 예약 가능 여부 대신 `예약 조건을 입력하면 가능 여부를 확인할 수 있어요.`
- 결과 없음: `조건에 맞는 매장이 없습니다. 지역이나 시간을 바꿔보세요.`

#### 포함하지 않을 요소

지도, 현재 위치, 거리순, 자연어 추천, 웨이팅 수, 결제 정보.

#### 선택 요소

최근 검색어, 인기 카테고리, 데스크톱 필터 사이드바.

### 4. 매장 상세 화면

#### 화면 목적

매장 기본정보·운영시간·대표 메뉴·예약 가능 시간을 확인하고 예약 또는 픽업으로 진입한다.

#### 반드시 포함할 요소

- 매장명, 설명, 주소·지역, 카테고리·태그
- 영업 중·임시 휴무·영업 종료 상태
- 요일별 운영시간과 브레이크타임
- 대표 메뉴 카드: 이름, 설명, 가격, 판매 가능 상태
- 예약 조건 요약 및 `예약하기`
- 등록 업종과 무관하게 `pickupEnabled`가 활성화된 픽업 가능 매장에만 `픽업 예약`

#### 화면 상태

기본, 상세 로딩, 매장 없음, 임시 휴무, 예약 불가, 메뉴 없음, 오류.

#### 이동

- 예약하기 → 날짜·시간·인원 선택
- 픽업 예약 → 픽업 메뉴·시간 선택
- 로그인하지 않았다면 선택 내용을 보존하고 로그인 후 복귀

#### 포함하지 않을 요소

리뷰, 지도, 거리, 매장 승인 상태, 웨이팅, 결제, 운영자 연락처.

### 5. 예약 날짜·시간·인원 선택 화면

#### 화면 목적

일반 방문 예약의 날짜, 시작 시간, 성인·아동·영유아 인원을 확정한다.

#### 반드시 포함할 요소

- 단계 표시: 예약 정보 → 메뉴 선택 → 확인
- 매장 요약, 날짜 달력, 가능한 시작 시간
- 성인·아동·영유아 수량 조절기와 총인원
- 운영시간·브레이크타임 안내
- 이전, 다음 버튼

#### 화면 상태와 문구

- 날짜 미선택, 시간 로딩, 이용 가능, 마감, 영업 외, 인원 범위 오류, 마지막 자리 충돌
- 충돌: `선택한 시간의 예약 가능 인원이 변경되었습니다. 다른 시간을 선택해 주세요.`
- 중복: `같은 매장에 시간이 겹치는 예약이 있습니다.`

#### 포함하지 않을 요소

종료 시간 직접 입력, 연락처 입력, 좌석 선택, 결제, 승인 대기, 웨이팅 전환.

### 6. 대표 메뉴 사전 선택 화면

#### 화면 목적

예약과 함께 홀드할 대표 메뉴와 수량을 선택하거나 메뉴 없이 계속 진행한다.

#### 반드시 포함할 요소

- 예약 조건 요약
- 홀드 가능 메뉴 카드: 이름, 설명, 가격, 잔여 수량, 수량 조절
- 선택 메뉴·수량·금액 요약
- `메뉴 없이 예약`, `예약 내용 확인`
- 메뉴 홀드는 식사 주문·결제가 아니라는 안내

#### 화면 상태와 문구

- 로딩, 선택 없음, 선택 있음, 품절, 수량 변경, 일부 또는 전체 수량 부족
- 부족: `선택한 메뉴의 수량이 부족합니다. 다시 선택하거나 메뉴 없이 예약해 주세요.`

#### 처리 원칙

하나라도 확보할 수 없으면 가능한 메뉴만 조용히 제거하지 않는다. 사용자가 전체 선택을 다시 판단한다.

#### 포함하지 않을 요소

별도 홀드 확정 버튼, 10분 타이머, 결제, 옵션, 대체 메뉴 자동 선택.

### 7. 예약 최종 확인 화면

#### 화면 목적

예약 생성 전 매장·일시·인원·선택 메뉴를 마지막으로 확인한다.

#### 반드시 포함할 요소

- 매장, 날짜, 시작 시간, 인원 구성
- 선택 메뉴·수량 또는 `선택한 메뉴 없음`
- 취소 정책 안내
- 수정 링크, 최종 예약 버튼
- 중복 제출 방지를 위한 처리 중 상태

#### 화면 상태와 문구

기본, 생성 중, 수용량 부족, 메뉴 부족, 중복 예약, 정책 변경, 성공.

#### 성공 후 이동

예약 완료 화면으로 이동한다. 성공 상태는 `예약 완료` 하나만 사용한다.

#### 포함하지 않을 요소

결제 단계, 확정 대기, 매장 승인, 임시 선점 카운트다운.

### 8. 예약 완료·상세 화면

#### 화면 목적

생성된 본인 예약의 현재 상태와 스냅샷을 확인하고 허용된 경우 취소한다.

#### 반드시 포함할 요소

- 예약 완료 메시지와 예약 식별번호
- 상태: 예약 완료·취소·방문 완료
- 매장명·주소, 날짜·시간, 인원 구성
- 선택 메뉴·수량, 예약 당시 정보
- 취소 가능 시 `예약 취소`, 목록 이동
- 취소 확인 모달과 완료 결과

#### 화면 상태와 문구

로딩, 예약 완료, 취소 완료, 방문 완료, 찾을 수 없음, 취소 불가, 처리 충돌.

#### 포함하지 않을 요소

예약 시간·인원 수정, 결제·환불, 체크인, 노쇼, 다른 사용자 정보.

### 9. 내 예약 목록 화면

#### 화면 목적

본인의 예약 확정·취소·방문 완료 내역을 날짜·상태로 조회한다.

#### 반드시 포함할 요소

- 상태 필터, 날짜 필터, 페이지 이동
- 카드 또는 행: 상태, 매장, 날짜·시간, 총인원, 대표 메뉴 요약
- 상세 이동

#### 화면 상태

로딩, 전체 없음, 필터 결과 없음, 오류, 페이지 끝.

#### 포함하지 않을 요소

웨이팅·결제·환불·노쇼 내역을 같은 목록에 혼합하지 않는다.

### 10. 픽업 선택 화면

#### 화면 목적

좌석 예약 없이 픽업 날짜·시간과 메뉴 수량을 선택한다.

#### 반드시 포함할 요소

- `픽업 예약` 표시와 일반 예약과의 차이 안내
- 픽업 날짜·가능 시간
- 메뉴명·가격·잔여 수량·수량 조절
- 선택 요약, 최종 확인·생성

#### 화면 상태와 문구

픽업 불가 매장, 제공 시간 없음, 메뉴 품절, 수량 충돌, 생성 중, 성공.

#### 성공 후 이동

픽업 예약 상세로 이동한다.

#### 포함하지 않을 요소

성인·아동·영유아, 팀 수, 좌석, 수령 준비 완료 상태, 결제.

### 11. 픽업 예약 상세 화면

#### 화면 목적

생성 직후 이동한 본인 픽업 예약의 예약 완료·취소·수령 완료 상태를 조회하고 취소한다. 현재 1차 MVP에는 일반 사용자 픽업 목록 조회 계약이 없으므로 목록 화면이나 내역 링크를 만들지 않는다.

#### 반드시 포함할 요소

- 상세: 매장 주소, 메뉴 스냅샷, 생성 시각, 취소 가능 여부
- 취소 확인 모달, 수령 완료 표시

#### 화면 상태

상세 없음, 취소 불가, 취소 완료, 수령 완료.

#### 포함하지 않을 요소

준비 완료, 배달, 좌석 예약 인원, 결제·환불.

### 12. 마이페이지·프로필 수정 화면

#### 화면 목적

이메일·휴대전화·닉네임·계정 상태를 확인하고 닉네임만 수정한다.

#### 반드시 포함할 요소

- 읽기 전용 이메일·휴대전화·계정 상태
- 닉네임 편집, 저장·취소
- 최근 변경 후 7일 제한 안내
- 내 예약 이동. 픽업 내역은 목록 API가 승인되기 전까지 추가하지 않는다.

#### 화면 상태와 문구

조회 로딩, 수정 가능, 형식 오류, 변경 제한, 저장 중, 완료, 충돌.

#### 포함하지 않을 요소

1차 MVP에서는 이메일·휴대전화·비밀번호 변경, 탈퇴, 프로필 이미지, 결제·알림·웨이팅 탭.

## 2차 MVP 화면

### 13. 자연어 검색·추천 결과 화면

#### 화면 목적

사용자의 문장에서 분위기·메뉴·거리·가격대 조건을 추출해 추천 결과를 보여준다.

#### 반드시 포함할 요소

- 자연어 입력창과 예시 문장
- 추출 조건 칩과 수정·삭제
- 추천 매장·메뉴, 추천 이유, 예약 가능 여부
- 일반 필터 검색으로 전환

#### 화면 상태

입력 전, 해석 중, 조건 확인, 결과 있음·없음, 해석 실패, 일부 조건 미지원.

#### 포함하지 않을 요소

추천 결과 자동 예약, 사용자가 말하지 않은 민감 조건의 추정.

### 14. 품절 대체 메뉴·주변 매장 추천 화면

#### 화면 목적

선택 메뉴가 품절됐을 때 같은 매장의 대체 메뉴를 먼저, 없으면 주변 매장을 제안한다.

#### 반드시 포함할 요소

- 품절된 원래 메뉴와 실패 이유
- 같은 매장 대체 메뉴: 카테고리·가격·가능 수량 비교
- 주변 매장: 거리, 동일 카테고리, 예약 가능 여부
- 대체 메뉴 선택, 원래 예약으로 돌아가기, 메뉴 없이 진행
- 다른 매장 선택 시 예약 조건 재확인 경고

#### 화면 상태

대체 검색 중, 같은 매장 결과, 주변 매장 결과, 대안 없음, 추천 갱신.

### 15. 지도·목록 탐색 화면

#### 화면 목적

카카오맵과 목록을 전환하며 주변 추천 매장을 탐색한다.

#### 반드시 포함할 요소

- 지도/목록 전환, 현재 검색 영역, 위치 권한 안내
- 매장 핀과 선택 카드, 거리·카테고리·예약 가능 여부
- 위치 거부·지도 로딩 실패 시 목록 유지

#### 포함하지 않을 요소

지도 사용 강제, 위치 상시 추적, 백그라운드 위치 수집.

## 고도화 화면

### 16. 소셜 로그인 확장 화면

#### 화면 목적
카카오 계정으로 일반 사용자 인증을 시작하거나 기존 계정 연결 문제를 안내한다.
#### 반드시 포함할 요소
카카오 로그인, 이메일 로그인 구분, 개인정보 제공 안내, 취소·재시도, 기존 계정 충돌 안내.
#### 화면 상태
연결 시작, 외부 이동, 동의 취소, 연결 중, 기존 계정 충돌, 성공, 실패.
#### 성공 후 이동
원래 접근 화면 또는 매장 찾기. 네이버·Google·Apple은 제공자 확정 전 제외한다.

### 17. 예약금 결제·결과 화면

#### 화면 목적
예약금 또는 메뉴 홀드 결제를 요청하고 최종 결과를 확인한다.
#### 반드시 포함할 요소
예약 요약, 결제 대상·금액, 결제수단, 결제 버튼, 취소 정책, 이탈 경고, 결과 재조회.
#### 화면 상태
결제 전, 처리 중, 성공, 명확한 실패, 결과 확인 중, 시간 초과, 재조회 후 확정.
#### 포함하지 않을 요소
결제 성공과 예약 확정을 서버 확인 전에 낙관적으로 동일 처리하지 않는다.

### 18. 결제·환불 내역 화면

#### 화면 목적
본인의 예약금 결제와 환불 이력을 확인한다.
#### 반드시 포함할 요소
기간·상태 필터, 결제일, 매장, 예약, 금액, 결제·환불 상태, 상세 영수 정보.
#### 화면 상태
내역 없음, 조회 중, 결제 확인 중, 환불 처리 중·완료·실패, 조회 오류.
#### 포함하지 않을 요소
카드번호·계좌번호 원문과 다른 사용자의 거래.

### 19. 웨이팅 등록 화면

#### 화면 목적
매장 웨이팅에 등록하고 예약과의 충돌을 해결한다.
#### 반드시 포함할 요소
매장, 인원, 현장·원격 조건, 예상 대기, 위치 확인 안내, 등록 확인, 취소.
#### 화면 상태
등록 가능·불가, 위치 권한 거부, 처리 중, 중복 웨이팅, 예약 충돌, 성공.
#### 성공 후 이동
현재 웨이팅 상세. 예약과 웨이팅을 동시에 유지할 수 없으면 사용자가 하나를 선택한다.

### 20. 현재 웨이팅 상세 화면

#### 화면 목적
현재 순번과 호출 상태를 실시간으로 확인하고 웨이팅을 취소한다.
#### 반드시 포함할 요소
현재 순번, 앞 팀 수, 예상 대기, 등록 정보, 실시간 연결, 마지막 갱신, 취소.
#### 화면 상태
대기, 호출, 입장 완료, 취소, 미응답, 연결 끊김, 재연결.
#### 포함하지 않을 요소
예상 대기시간을 확정 입장 시각처럼 표현하지 않는다.

### 21. 체크인·노쇼 대응 화면

#### 화면 목적
도착을 증명하고 노쇼 후보 상태에서 제한 시간 안에 대응한다.
#### 반드시 포함할 요소
QR 또는 일회용 확인번호, 유효시간, 입력·스캔 안내, 예약 요약, 도움 요청.
#### 화면 상태
체크인 가능, 처리 중, 성공, 코드 오류·만료, 노쇼 후보, 남은 시간, 노쇼 확정.
#### 포함하지 않을 요소
사용자가 노쇼 상태를 직접 선택하거나 QR 원문을 장기 노출하지 않는다.

### 22. 알림 목록·상세 화면

#### 화면 목적
서비스 알림을 유형별로 확인하고 관련 화면으로 이동한다.
#### 반드시 포함할 요소
전체·읽지 않음 필터, 유형, 제목, 요약, 시각, 읽음 상태, 관련 화면 링크.
#### 화면 상태
알림 없음, 로딩, 새 알림, 링크 대상 만료, 목록 오류, 읽음 처리 실패.
#### 알림 유형
예약 완료·취소, 메뉴 품절, 방문 시간, 웨이팅 호출, 대체 메뉴·주변 매장, 취소표.
#### 포함하지 않을 요소
알림 전송 실패가 원 예약 상태를 변경한 것처럼 표현하지 않는다.

## 최종 산출물 요구

각 화면은 데스크톱과 모바일 변형을 제공한다. 위 화면마다 기본·로딩·빈 상태·검증 오류·서버 오류·성공 상태를 최소 한 장씩 제시하고, 클릭 가능한 주요 이동 관계를 프로토타입으로 연결한다. 1차 MVP 전용 산출물, 2차 추가 산출물, 고도화 추가 산출물을 구분해 전달한다.
