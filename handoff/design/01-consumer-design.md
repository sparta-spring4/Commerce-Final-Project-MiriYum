# MiriYum 일반 사용자 UI 디자인 인계서

## 1. 목적과 역할 경계

이 문서는 일반 사용자가 매장을 탐색하고 일반 예약 또는 픽업 예약을 관리하는 화면을 설계하기 위한 독립형 요구사항이다. 일반 사용자 화면에는 매장 운영, 입점 심사, 플랫폼 운영 기능을 넣지 않는다.

모든 단계의 기능은 독립된 페이지·탭·카드·행동 단위로 구성한다. 미래 모듈을 제거해도 탐색, 매장 상세, 일반 예약, 마이페이지의 레이아웃에 빈 영역이 남거나 핵심 흐름이 끊기지 않아야 한다. 최종 화면에는 개발 단계명을 노출하지 않는다.

## 2. 단계별 화면 범위

| 단계 | 독립 모듈 | 일반 사용자 경험 |
| --- | --- | --- |
| 1차 MVP | 가입·로그인·내 계정, 검색, 매장 상세, 일반 예약, 메뉴 사전 선택, 픽업, 예약·픽업 내역 | 조건에 맞는 매장을 찾고 즉시 확정되는 예약 또는 픽업을 생성·조회·취소한다. |
| 2차 MVP | 자연어 탐색, 개인화 추천, 대체 메뉴·주변 매장 추천, 카카오맵 | 사용자가 의도를 확인·수정하며 더 적합한 매장과 메뉴를 비교한다. |
| 고도화 | 결제·환불, 알림, 웨이팅, 취소 자리 자동 승계·빈자리 알림, 웨이팅 기반 지도 추천(1km~5km), 체크인·노쇼, 카카오 소셜 로그인·세션, 마이페이지 내역 모듈 | 거래 이후와 방문 당일의 상태를 관리하고 관련 이력을 확인한다. |

## 3. 1차 MVP

### 3.1 일반 사용자 가입과 로그인

- 일반 사용자 전용 가입·로그인임을 제목과 진입 문구로 분명히 한다. 매장명, 사업자 정보, 운영자 역할 선택은 포함하지 않는다.
- 가입은 계정 정보, 비밀번호 확인, 공개 닉네임, 신뢰 연락처, 만 14세 이상 자기 확인으로 구성한다. 신뢰 연락처와 연령 확인은 이메일 또는 휴대전화의 소유 인증을 완료했다는 뜻으로 표현하지 않는다.
- 로그인은 계정 식별 정보와 비밀번호, 표시/숨김, 가입 이동, 형식 오류, 인증 실패, 요청 제한, 처리 중 상태를 제공한다.
- 가입 완료, 로그인 완료, 실패 후 재입력 흐름을 분명히 하며 카카오 소셜 로그인과 세션 관리 화면은 고도화 모듈로 분리한다.

### 3.2 내 계정·프로필

- 내 계정 화면은 계정 정보, 공개 닉네임, 마스킹된 신뢰 연락처와 등록 상태, 일반 예약·픽업 내역 진입을 제공한다. 연락처가 아직 없을 때에만 1회 등록 경로를 보여 준다.
- 신뢰 연락처 등록 화면은 입력, 저장 중, 저장 완료, 형식 검증 오류, 서버가 보고한 충돌·실패, 재시도 상태를 제공한다. 등록 후에는 마스킹된 값과 등록 완료 상태만 보이며 이메일 또는 등록된 전화번호의 교체 화면을 만들지 않는다.
- 공개 닉네임 수정은 현재 값, 입력 검증, 저장 중, 저장 완료, 서버가 보고한 충돌, 실패 후 재시도 상태를 제공한다. 저장 완료 전에는 이전 값을 유지하고, 저장 결과와 화면 상태가 어긋나지 않게 한다.
- 이 화면은 이메일·휴대전화 소유 인증, 이메일·등록 전화번호 교체, 비밀번호 재설정, 소셜 로그인, 세션 관리 기능을 제공하지 않는다.

### 3.3 매장 탐색과 검색

- 검색 입력은 키워드, 지역, 매장 카테고리, 서비스 날짜, 시작 시간, 일행 수, 영유아 포함 여부, 완전 조건 일치 가능 여부를 함께 다룬다.
- 지역 필터는 서울, 부산, 대구, 대전, 광주 다섯 곳을 제공한다.
- 키워드는 매장명, 대표 메뉴, 지역명 탐색 의도를 수용한다. 카테고리와 검색 조건은 개별 해제와 전체 초기화가 가능해야 한다.
- 날짜·시작 시간·일행 수·영유아 포함 여부가 모두 갖춰진 경우에만 완전 조건의 예약 가능 여부를 결과 카드와 목록에 표시한다. 조건이 불완전하면 가능 여부를 확정적으로 보이지 않는다.
- 결과 화면은 결과 수, 정렬·페이지 이동 또는 더 보기, 결과 없음, 조건 수정, 로딩을 포함한다. 매장 카드는 매장명, 지역·주소, 카테고리, 운영 상태와 조건이 완전할 때의 예약 가능 여부를 읽기 쉽게 보여 준다.

### 3.4 매장 상세와 진입점

- 상세는 매장명, 설명, 지역, 주소, 카테고리, 태그, 현재 운영 상태, 요일별 운영시간·브레이크타임, 대표 메뉴를 제공한다. 대표 메뉴에는 이름, 설명, 가격, 소비자에게 의미 있는 판매 가능 여부와 품절 여부만 표시하며 공개되지 않는 메뉴는 목록에서 생략한다.
- 일반 예약과 픽업은 서로 독립된 진입점으로 배치한다. 한 흐름의 입력이나 요약이 다른 흐름으로 이어지지 않게 한다.
- 일반 예약 진입점은 날짜와 인원 선택으로 연결한다. 픽업 진입점은 픽업 제공 매장에서만 픽업 전용 흐름으로 연결한다. 업종으로 픽업을 제한하지 않는다. 카페·베이커리 한정은 금지한다.
- 공개 일정은 운영시간과 일반 예약에 필요한 일정 정보를 이해할 수 있게 보여 주되, 선택할 수 없는 시간대를 예약 가능한 것처럼 보이지 않는다.

### 3.5 일반 예약과 대표 메뉴 사전 선택

1. 매장 요약에서 날짜, 시작 시간, 성인·아동·영유아 인원을 선택한다.
2. 선택 요약을 확인한 뒤 대표 메뉴 사전 선택으로 이동하거나 메뉴 없이 진행하는 `건너뛰기`를 선택한다.
3. 메뉴 선택 화면은 메뉴명, 설명, 가격, 선택 수량, 선택 가능 여부를 제공한다. 예약과 메뉴 수량 확보는 전체 성공 또는 전체 실패로 표시한다. 일부 메뉴만 조용히 확정된 것처럼 보이면 안 된다.
4. 수량 부족·품절·동시 예약 충돌에서는 선택을 다시 검토하거나 메뉴 없이 예약하는 경로를 명확히 제공한다.
5. 완료 화면과 상세는 예약번호, 매장명, 방문 날짜·시간, 인원 구성, 선택 메뉴와 수량 또는 메뉴 없음, 예약 상태, 취소 행동과 확인 단계를 제공한다.
6. 마이페이지의 일반 예약 내역은 완료·취소·방문 완료 상태를 구분하고, 빈 내역, 조회 실패, 페이지 이동과 상세 이동을 제공한다.

결제, 환불, 체크인, 노쇼, 예약 변경, 승인 대기는 일반 예약 흐름에 섞지 않는다.

### 3.6 서비스별 재고 경계

- 일반 예약 메뉴 홀드는 예약 전용 재고만 소비하고, 일반 예약 취소 시 같은 예약 전용 재고로만 복구한다.
- 픽업은 픽업 전용 재고만 소비하고, 픽업 취소 시 같은 픽업 전용 재고로만 복구한다.
- 한 서비스의 가용량, 품절, 소비, 취소 복구는 다른 서비스의 재고를 변경하거나 합산하지 않는다. 두 재고를 하나의 공유 수량처럼 표시하지 않는다.
- 서비스 간 재고 이전은 향후 결정할 사항이다. 이전 정책이 확정되기 전에는 이전 버튼, 이전 화면·경로, 이전 상태, 수량 한도, 감사 이력, API, placeholder 흐름을 만들지 않는다.

### 3.7 전 업종 픽업

- 픽업은 픽업 기능을 제공하는 모든 업종의 매장에서 사용한다. 좌석 예약 인원이나 팀 수를 픽업 화면에 넣지 않는다.
- 픽업 흐름은 매장과 픽업 전용 날짜, 시간, 메뉴, 수량을 선택하고 가용 수량·품절을 확인한 뒤 픽업 예약 요약과 완료로 이어진다.
- 픽업 완료와 상세는 픽업 예약번호, 매장, 픽업 날짜·시간, 메뉴·수량, 상태, 취소를 제공한다. 상태는 예약 완료, 취소, 수령 완료로 구분한다.
- 마이페이지에는 일반 예약 내역과 독립된 픽업 내역·상세·취소 흐름을 둔다.

## 4. 2차 MVP 탐색 확장

- 기존 키워드·필터 검색을 보존한 채 자연어 입력을 별도 모드로 추가한다. 분위기, 메뉴 카테고리, 거리, 가격대의 추출 조건을 사용자가 검토하고 수정할 수 있어야 한다.
- 이전 예약과 최근 메뉴 홀드 이력을 반영한 선호 기반 추천은 추천 이유와 적용 조건을 함께 보여 주며 자동 확정처럼 보이지 않게 한다.
- 품절 시 같은 카테고리의 대체 메뉴를 원래 메뉴와 가격, 카테고리, 가용성 기준으로 비교한다.
- 같은 매장에 대체 메뉴가 없으면 반경 3km 내 주변 매장을 제안하고 원래 매장과 다른 매장임을 명확히 표시한다.
- 메뉴 카테고리, 가격대, 거리, 예약 가능 여부를 반영한 우선순위와 이유를 표시한다.
- 카카오맵 화면은 목록 탐색과 분리하며, 지도 모듈이 빠져도 검색·결과·상세 흐름은 유지되어야 한다.

## 5. 고도화 모듈

- 결제·예약금·환불은 결제 입력, 처리 중, 성공, 실패, 취소, 환불 및 거래 내역을 독립 모듈로 설계한다.
- 알림 내역은 예약 완료·취소, 메뉴 품절, 방문 시간, 웨이팅 호출, 대체 추천을 종류별로 구분한다.
- 웨이팅은 등록, 순번, 예상 대기, 취소, 호출, 입장 완료, 미응답을 독립 흐름으로 제공한다.
- 체크인은 QR 또는 일회용 번호 확인으로, 노쇼는 취소 자리 자동 승계와 분리된 별도 상태와 안내로 구성한다.
- 취소 자리 자동 승계와 빈자리 알림의 유일한 시작 사건은 확정된 일반 예약의 유효한 일반 취소다. 노쇼 후보·확정·정정은 취소가 아니며 자동 승계, 예약 수용량 반환 원장, 일반 예약 가용성 재게시를 절대로 만들지 않는다. 체크인·노쇼는 독립 모듈로 유지하고, 확정되지 않은 승계 제한 시간·우선순위·상태를 발명하지 않는다.
- 웨이팅 기반 지도 추천은 지도에서 대기 맥락과 거리 정보를 함께 설명하는 독립 탐색 모듈이다. 거리 경계는 `1km~5km`이며 기본 반경, 순위, 추가 거리 정책을 발명하지 않는다. 2차 MVP의 대체 메뉴용 3km 규칙과 합치거나 재사용하지 않는다.
- 카카오 소셜 로그인과 세션은 계정 진입·보안 설정의 독립 모듈로 둔다.
- 마이페이지에는 결제·환불, 알림, 웨이팅, 예약·픽업 이력 모듈을 각각 독립적으로 추가한다.

## 6. 모든 화면의 상태 설계

- 로딩: 최초 로딩, 필터 변경, 저장·취소 처리, 재조회가 서로 구분되게 한다.
- 빈 상태: 검색 결과 없음, 예약·픽업·알림·웨이팅 내역 없음에 맞는 다음 행동을 제공한다.
- 검증: 필수 입력, 날짜·시간, 인원·수량, 형식 오류를 입력 위치와 요약 영역에서 함께 설명한다.
- 동시성 충돌: 예약 또는 수량이 다른 사용자 행동으로 바뀌면 오래된 선택임을 알리고 최신 상태 재조회와 안전한 재선택을 제공한다.
- 권한: 일반 사용자 전용 정보와 행동은 인증 필요 상태를 명확히 안내하며 다른 역할 화면으로 전환시키지 않는다.
- 네트워크: 연결 끊김, 시간 초과, 서버 오류에서 입력과 확정 결과를 혼동하지 않게 한다.
- 오래된 상태와 재시도: 검색·상세·가용성 정보의 시점 차이를 표시하고, 같은 의도의 재시도와 새로운 예약 시도를 구별할 수 있게 한다.

## 7. 산출물 요구

각 화면은 모바일 우선 정보 구조와 데스크톱 확장 구조, 필수 컴포넌트, 기본·로딩·빈·검증·오류·완료 상태, 주요 이동 경로를 제시한다. 색상만으로 상태를 구분하지 않고 텍스트, 아이콘, 형태를 함께 사용한다. 미래 모듈이 빠진 1차 MVP 변형에서도 빈 카드, 빈 탭, 비활성 버튼, 준비 중 화면을 남기지 않는다.
