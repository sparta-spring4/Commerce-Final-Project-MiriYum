# MiriYum 플랫폼 운영자 UI 디자인 인계서

## 1. 목적과 적용 단계

이 문서는 플랫폼 운영자 전용 화면을 설계하기 위한 독립형 요구사항이다. 플랫폼 운영자 기능 전체는 **고도화** 범위이며, 1차 MVP와 2차 MVP의 실제 서비스에서는 운영자 로그인, 셸, 내비게이션, 라우트, 탭, 제어 요소를 전부 노출하지 않는다. 이 문서의 화면은 향후 완전한 운영 기능을 위한 디자인이며, 화면 존재만으로 실제 연결이나 권한 부여를 뜻하지 않는다.

정확한 API 경로, 권한 이름, 상태값, 처리 기한·평균치·통계 수치는 결정하지 않는다. 정해지지 않은 정책을 수치나 버튼 동작으로 보완하지 않는다.

## 2. 역할과 진입 경계

- 플랫폼 운영자는 일반 사용자 및 매장 운영자와 분리된 계정, 로그인, 세션 맥락, 서비스 셸을 사용한다.
- 공개 가입이나 다른 계정의 역할 선택으로 플랫폼 운영자가 될 수 있는 흐름을 설계하지 않는다.
- 일반 사용자와 매장 운영자 로그인 화면으로 돌아가는 안내는 제공할 수 있으나, 두 계정으로 플랫폼 화면에 들어오는 교차 진입은 허용하지 않는다.
- 로그인 뒤에는 현재 계정, 접근 가능한 업무 범위, 민감한 정보를 열람·조치할 수 있는지 여부를 분명히 보여 준다. 확인되지 않은 권한은 추측해 표시하지 않는다.
- 슈퍼관리자 전용 운영자 관리 영역은 다른 플랫폼 운영자 기능과 시각적·구조적으로 분리한다.

## 3. 공통 셸과 안전한 상호작용

### 3.1 셸과 내비게이션

독립된 운영자 로그인, 상단 계정·권한 맥락, 업무 목록, 목록/상세 화면의 일관된 구조를 사용한다. 기본 내비게이션은 다음 업무 단위로 구성한다.

- 회원 관리
- 입점 심사
- 매장 관리
- 예약 관리
- 웨이팅 관리
- 대표 메뉴·추천 메뉴 운영 검토
- 운영자 관리(슈퍼관리자 전용)

권한이 없는 업무는 접근 불가 상태를 명확히 안내하되, 권한의 존재나 이름을 임의로 만들어 내지 않는다. 일반 사용자나 매장 운영자의 일상 기능을 운영자 셸의 메뉴로 옮기지 않는다.

### 3.2 목록·상세·감사 패턴

대량 목록은 검색·필터의 적용 상태, 전체 결과, 페이지 이동, 빈 결과, 재조회와 실패 상태를 함께 보여 준다. 목록에는 업무 판단에 필요한 최소 식별 정보만 두고, 민감 정보는 권한이 확인된 상세 화면에서만 별도로 다룬다.

승인, 반려, 정보 정정, 비활성화, 운영 중지, 사건 조치, 운영자 계정 발급·중지·권한 변경처럼 영향이 큰 작업은 다음을 거친다.

1. 대상, 범위, 예상 영향 및 되돌릴 수 없는 결과를 읽을 수 있게 한다.
2. 조치 사유를 입력하고, 필요한 확인 단계를 완료하게 한다.
3. 처리 중에는 중복 실행을 막고 결과가 확정될 때까지 완료로 보이지 않게 한다.
4. 결과에는 담당자, 처리 시각, 사유와 감사에 필요한 조치 맥락을 남긴다.

모든 업무 화면은 로딩, 빈 결과, 조회 실패, 권한 부족, 동시 변경, 이미 처리됨, 필수 사유 누락, 처리 성공, 부분 실패, 전체 실패를 설계한다. 부분 실패에서는 완료된 범위와 다시 확인할 범위를 혼동하지 않게 구분한다.

## 4. 업무 화면

### 4.1 플랫폼 운영자 로그인

- 플랫폼 운영자 전용 로그인임을 나타내는 제목과 안내
- 자격 증명 입력, 로그인 진행, 인증 실패·권한 없음·처리 중 상태
- 일반 사용자·매장 운영자 로그인과 구분되는 지원 안내

공개 회원가입, 역할 선택, 다른 계정의 전환 또는 테스트용 계정 표시는 포함하지 않는다.

### 4.2 회원 관리

- 일반 사용자와 매장 운영자 구분, 현재 계정 상태 및 제한 이력 중심의 검색·필터
- 최소 식별 정보가 있는 목록과, 권한별로 나뉜 상세 정보
- 허용된 제한·해제 또는 사건 대응 조치의 사유·확인·결과
- 개인정보 최소 노출, 민감 정보 열람의 별도 권한·감사 맥락

계정의 일상 프로필 편집이나 매장 운영자의 사업 운영을 플랫폼 업무로 대체하지 않는다.

### 4.3 입점 신청·제출 자료 심사

- 신청 목록, 신청 맥락, 제출 자료 검토, 처리 이력, 담당자와 처리 시각
- 승인 또는 반려, 결정 사유, 동시 처리 및 이미 종결된 신청 상태
- 자료가 부족하거나 열람 권한이 없는 경우의 안전한 안내

입점 신청과 문서 검토는 고도화 기능이다. 이는 1차 MVP에서 매장 운영자가 승인 대기 없이 매장을 등록하고 관리하는 흐름을 대체하거나 그 등록에 심사 단계를 삽입하지 않는다.

### 4.4 매장 관리

- 매장명·지역·업종·카테고리와 현재 운영 맥락을 기준으로 한 탐색
- 매장 기본 정보와 조치 이력을 확인하는 상세 화면
- 정보 정정, 매장 비활성화, 운영 중지의 영향 안내·사유·확인·결과
- 기존 예약이나 진행 중 사건에 영향을 줄 수 있는 경우의 확인 및 감사 맥락

플랫폼 운영자는 매장 서비스의 일상 운영, 메뉴 편집, 메뉴 홀드 재고 또는 다른 재고를 직접 수정하는 화면을 갖지 않는다.

### 4.5 예약 관리

- 매장·기간·현재 예약 맥락을 통한 사건 탐색
- 예약 식별 정보, 매장, 최소 사용자 정보, 방문 정보와 사건 관련 이력의 상세
- 권한 있는 플랫폼 조치의 가능 여부, 사유, 확인, 결과와 감사 정보

이 영역은 예외·분쟁·복구·제재와 같은 플랫폼 사건 관리 경계다. 매장 운영자가 수행하는 일상적인 예약 확인, 취소, 방문 완료 업무를 대신하는 흐름으로 설계하지 않는다.

### 4.6 웨이팅 관리

- 매장·기간·현재 대기 맥락으로 사건을 찾아볼 수 있는 목록
- 대기 흐름과 이상 징후, 실시간 전달 상태, 사건 이력의 상세
- 허용된 플랫폼 복구 또는 제재 조치의 사유·확인·결과

개별 매장의 정상적인 순번 운영과 호출은 매장 운영자 영역에 남긴다. 플랫폼 화면은 사건 관리 경계를 넘어서 일상 웨이팅 운영을 대체하지 않는다.

### 4.7 대표 메뉴·추천 메뉴 운영 검토

- 매장별 대표 메뉴와 추천 메뉴의 공개·운영상 맥락을 검토하는 목록과 상세
- 사용자 노출에 영향을 주는 문제의 확인, 허용된 플랫폼 조치의 사유·확인·감사 결과
- 추천 결과의 근거와 정책이 결정되지 않은 경우에는 수치·순위·평균을 단정하지 않는 상태

이 영역은 플랫폼 경계의 운영 검토다. 매장 서비스의 메뉴 구성이나 재고를 편집하는 우회 화면을 만들지 않는다.

### 4.8 운영자 관리

운영자 관리는 **슈퍼관리자에게만** 보인다.

- 플랫폼 운영자 목록, 현재 업무 범위 또는 권한 요약, 최근 중요 조치
- 플랫폼 운영자 계정 발급, 중지, 권한 관리
- 각 고위험 조치의 대상·영향·사유·확인·결과와 감사 맥락

일반 플랫폼 운영자가 다른 운영자 계정을 조회·발급·중지·권한 변경할 수 있는 것처럼 보이게 하지 않는다.

## 5. 산출물 기준

각 화면은 목적과 대상 권한, 목록·필터·상세 구조, 주요 조치와 확인 단계, 기본·빈 결과·오류·권한 부족·처리 완료 상태, 개인정보 최소화 방식을 보여 준다. 슈퍼관리자 변형은 운영자 관리에만 명시적으로 적용하며, 이 문서의 모든 화면은 고도화가 실제로 연결될 때까지 독립적으로 숨길 수 있게 모듈화한다.
