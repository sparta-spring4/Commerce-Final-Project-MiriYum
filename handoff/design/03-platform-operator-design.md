> **직접 대조:** [`docs/01-product-vision.md`](../../docs/01-product-vision.md), [`docs/02-users-and-permissions.md`](../../docs/02-users-and-permissions.md), [`docs/05-functional-requirements.md`](../../docs/05-functional-requirements.md), [`docs/06-system-architecture.md`](../../docs/06-system-architecture.md)를 기준으로 한다. 현재 플랫폼 운영자용 승인 OpenAPI와 Controller는 없으므로 새 계약이 승인되기 전에는 실제 라우트·클라이언트·mock success를 만들지 않는다.

## 적용 범위

플랫폼 운영자 전체 화면은 고도화 전용이다. 1차 MVP와 2차 MVP 서비스에는 로그인·메뉴·라우트·버튼을 노출하지 않는다. 일반 사용자·식당 대표자 서비스와 독립된 운영 콘솔로 디자인한다.

공통 셸은 운영 콘솔 로고, 좌측 내비게이션, 현재 운영자·권한, 전역 검색, 알림, 로그아웃, 처리 사유와 감사 이력, 민감정보 마스킹을 포함한다. 일반 운영자와 슈퍼관리자 전용 기능을 시각적으로 구분한다.

### 1. 플랫폼 운영자 로그인

#### 화면 목적
발급된 운영자 계정으로 독립 콘솔에 진입한다.

#### 반드시 포함할 요소
운영 콘솔 표시, 이메일·비밀번호·표시/숨김, 로그인, 실패·잠금·세션 만료, 보안 안내. 최초 로그인 임시 비밀번호 변경이 필요한 경우 다음 단계 안내.

#### 상태와 문구
기본, 필수 오류, 처리 중, 통합 로그인 실패, 재시도 제한, 계정 중지, 최초 변경 필요, 세션 만료. 일반 사용자·대표자 회원가입 링크를 운영자 가입처럼 배치하지 않는다.

#### 성공 후 이동
권한에 따라 운영 홈 또는 최초 비밀번호 변경. 플랫폼 운영자 공개 회원가입은 제공하지 않는다.

### 2. 운영 홈

#### 화면 목적
권한 있는 운영자가 자신의 처리 업무와 이상 상황을 파악한다.

#### 반드시 포함할 요소
처리 대기 입점·신고·복구 사건, 시스템 이상 요약, 담당 업무 바로가기, 최근 처리, 데이터 기준 시각. 권한이 없는 카드와 수치를 숨긴다.

#### 상태
업무 없음, 일부 집계 지연, 전체 오류, 권한 제한.

### 3. 회원 목록·상세 관리

#### 화면 목적
일반 사용자·식당 대표자 계정을 검색하고 권한 범위의 제재·복구 업무를 수행한다.

#### 반드시 포함할 요소
- 목록: 계정 유형, 마스킹 식별정보, 상태, 가입일, 최근 상태 변경
- 필터: 사용자 유형, 상태, 가입 기간, 내부 식별자
- 상세: 기본정보, 제재·복구 사건, 예약 등 관련 항목으로의 안전한 이동
- 허용된 조치: 경고·기능 제한·기간 정지·영구 정지 제안, 사유, 확인

#### 상태와 안전장치
검색 전, 결과 없음, 상세 권한 없음, 동시 변경, 재인증 필요, 처리 완료. 목록에서 한 번의 아이콘 클릭으로 제재가 즉시 확정되지 않게 한다. 민감 원문은 별도 권한·재인증 없이 보여주지 않는다.

### 4. 입점 신청 목록

#### 화면 목적
심사가 필요한 신청을 조건별로 찾고 담당자를 배정한다.

#### 반드시 포함할 요소
신청 상태·업종·신청일·담당자 필터, 신청번호·매장명·대표자 마스킹·자동 검사 결과·상태·경과시간, 배정·상세 이동, 페이지네이션.

#### 상태
대기 없음, 자동 검사 보류, 보완 제출, 이미 다른 운영자가 처리, 목록 갱신 실패.

### 5. 입점 신청 상세·심사

#### 화면 목적
신청 자료와 검사 결과를 확인하고 승인·반려·보완 요청을 기록한다.

#### 반드시 포함할 요소
버전된 입력 사업자정보, 비공개 사업자등록증 보기, 자동 검사 결과, 불일치 항목, 신청 이력, 담당자, 승인·반려·보완 요청, 사유·보완 항목 입력, 확인 모달, 감사 기록.

#### 처리 원칙과 상태
로딩, 자료 접근 만료, 버전 변경, 처리 중, 승인·반려·보완 완료, 중복 처리. 자료가 변경되면 이전 판정을 그대로 재사용하지 않는다. 승인 전 공개·운영 차단은 이 고도화 흐름이 실제 활성화된 경우에만 적용한다.

### 6. 매장 목록·상세 관리

#### 화면 목적
플랫폼 차원의 매장 상태와 이상 사건을 조회하고 허용된 조치를 수행한다.

#### 반드시 포함할 요소
입점·운영 상태, 업종·지역·대표자, 신고·이상 상태 필터, 매장 기본정보·변경 이력·과거 거래 영향, 비활성화·운영 중지·잘못된 정보 대응, 사유·확인·감사 이력.

#### 포함하지 않을 요소
플랫폼 운영자가 일상적인 영업시간·메뉴·재고를 대신 편집하는 일반 매장 관리 UI.

### 7. 예약 목록·상세 관리

#### 화면 목적
플랫폼 지원·복구가 필요한 예약 사건과 연관 원장을 조회한다.

#### 반드시 포함할 요소
매장·기간·상태·사용자 내부 ID 필터, 예약 스냅샷, 상태 이력, 메뉴 홀드·결제·체크인·노쇼의 활성 단계별 독립 섹션, 복구 필요 사건, 허용된 수동 작업·사유·감사.

#### 안전장치
식당 대표자의 정상 방문 완료를 대신하는 화면으로 만들지 않는다. 금전·수량·상태 변경은 별도 권한과 재인증, 결과 재조회가 필요하다.

### 8. 웨이팅 전체 모니터링

#### 화면 목적
전체 매장의 웨이팅과 실시간 이상 상태를 모니터링한다.

#### 반드시 포함할 요소
매장·상태·기간 필터, 전체 대기 현황, 실시간 연결·마지막 갱신, 이상 패턴, 사건 상세. 개별 매장의 정상 호출은 대표자 화면이 담당한다.

### 9. 결제·환불 복구 작업

#### 화면 목적
결과 불명·중복·환불 실패 사건을 권한과 승인 기준에 따라 복구한다.

#### 반드시 포함할 요소
결제·예약 연결, 제공자 확인 상태, 중복·결과 불명·환불 실패, 담당자 배정, 허용 작업, 금액·권한별 추가 승인, 재인증, 감사 이력. 결제수단 원문은 표시하지 않는다.

### 10. 플랫폼 운영자 목록·생성

#### 화면 목적
슈퍼관리자가 플랫폼 운영자 계정을 발급하고 상태를 조회한다.

#### 대상 권한
슈퍼관리자 전용.

#### 반드시 포함할 요소
운영자 목록, 상태·권한·최근 로그인, 신규 생성, 임시 비밀번호 전달 상태, 상세 이동. 공개 가입이나 일반 사용자 승격을 제공하지 않는다.

### 11. 운영자 권한·상태 관리

#### 화면 목적
운영자별 업무 권한과 계정 상태를 안전하게 변경한다.

#### 반드시 포함할 요소
업무별 권한, 변경 전후 비교, 중지·재활성화, 사유, 재인증, 영향 범위, 확인 모달, 감사 이력. 자기 자신의 핵심 권한 제거와 마지막 슈퍼관리자 제거를 방지하는 상태를 디자인한다.

### 12. 감사 이력 조회

#### 화면 목적
운영 명령의 행위자·대상·결과와 변경 이력을 감사한다.

#### 반드시 포함할 요소
행위자·대상·업무·기간·결과 필터, 변경 전후의 허용된 요약, 사건 연결, 내보내기 권한, 상세 접근. 비밀번호·토큰·사업자증빙 원문·결제수단은 감사 화면에도 표시하지 않는다.

## 공통 화면 상태

모든 목록·상세·명령 화면은 로딩, 빈 결과, 권한 없음, 재인증 필요, 대상 변경·종결, 중복 처리, 부분 의존성 장애, 처리 성공 후 서버 재조회 실패를 포함한다. 낙관적으로 성공을 확정하지 말고 서버에서 재조회된 최종 상태와 처리 식별자를 표시한다.

## 최종 산출물 요구

각 화면에 데스크톱 중심 레이아웃과 축소형 태블릿 대응, 목록 컬럼, 필터, 상세 정보 그룹, 액션 위치, 사유 입력, 확인 모달, 권한별 변형, 모든 화면 상태, 이동 관계를 제시한다. 1차·2차 MVP에서는 전체 셸이 존재하지 않는다는 별도 가시성 명세도 제공한다.
