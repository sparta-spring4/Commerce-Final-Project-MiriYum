# 01. 제품 비전

## 서비스 정의

MiriYum은 사용자가 실제 이용 가능한 매장과 메뉴를 찾고 방문 기회를 확보하도록 돕고, 매장이 자신의 운영 방식에 맞는 예약 기능을 선택하도록 지원하는 양면 다이닝 플랫폼이다. 기능 수를 늘리는 것보다 계정·매장 귀속과 예약 자원의 정확성을 먼저 검증한다.

## 핵심 사용자

- 일반 사용자는 공개된 매장과 메뉴를 탐색하고 자신의 예약·메뉴 홀드·픽업 경험을 관리한다.
- 매장 운영자는 사업자 검증과 매장 소속 확인을 거쳐 자신에게 연결된 매장만 관리한다.
- 플랫폼 운영자는 `고도화`에서 입점 증빙 심사, 고객지원, 분쟁과 장애 대응을 부여된 업무 권한 안에서 수행한다. `1차 MVP`의 정상 고유 입점은 구조화 사업자 정보의 무료 공공 조회로 자동 확정한다.

## 네 단계 제품 가치와 비목표

| 단계 | 제공 가치 | 이 단계의 비목표 |
|---|---|---|
| `1차 MVP` | 분리된 세 계정 유형, 구조화 사업자 정보 자동 확인에 따른 매장 입점·소속 검증, 텍스트 기반 매장·메뉴 탐색과 정확한 예약을 통해 첫 사용자·매장 흐름을 검증한다. 매장은 거래별 활성 기능으로 `예약만`, `예약+메뉴 홀드`와 카페·베이커리로 확인된 매장의 `픽업 예약`을 사용한다. | 파일·이미지 업로드, 플랫폼 운영자 심사, 카카오 로그인, 서버 저장형 리프레시 토큰 회전·폐기·재사용 탐지, 리뷰, 구독, 광고, Pro 분석과 POS 전체 재고 연동을 제공하지 않는다. |
| `2차 MVP` | 1차 증거를 바탕으로 AI 없는 규칙 기반 해석, 이력 기반 추천, 품절 대안과 지도 탐색을 제공한다. | 웨이팅, 체크인·노쇼, 예약금·취소·환불, 취소 자원 승계, AI 개인화, 리뷰 생태계와 유료 상품을 활성화하지 않는다. |
| `고도화` | 웨이팅, 체크인·노쇼, 예약금·취소·환불과 취소 자원 승계로 거래·운영 흐름을 확장한다. Valkey 기반 리프레시 토큰 회전·폐기·재사용 탐지와 일반 사용자 카카오 로그인을 도입하고 관측된 품질·성능·운영 문제를 개선한다. | 이메일 일치나 외부 로그인 성공을 계정 유형·권한 변경 수단으로 사용하지 않으며, 장기 후보 기능을 자동으로 포함하지 않는다. |
| `향후 고도화` | 리뷰·취향 평가, 사용자 구독, 매장 Pro, 광고, 코스·테이스팅과 POS 연동을 실제 수요·법률·운영 증거가 있을 때 검토한다. | 후보를 출시 약속이나 현재 권한·상태·API의 선구현 근거로 사용하지 않는다. |

정책 결정 상태와 단계 포함 여부는 별도 축이다. 뒤 단계 기능은 해당 단계가 승인되기 전까지 현재 화면, 권한이나 거래 상태로 노출하지 않는다.

## 사용자 가치

- 사용자는 공개 정보와 실제 예약 가능 자원을 구분해 이해하고, 필요한 방문 인원·팀 수와 선택 메뉴 수량을 하나의 일관된 흐름에서 확보한다.
- 품절이나 운영 변경이 발생해도 대체·변경·취소는 사용자의 명시적 동의와 해당 거래 정책에 따라 처리된다.
- 운영 모드가 바뀌어도 이미 확정된 예약·메뉴 홀드·픽업 거래는 당시 조건과 상태가 보존된다.

## 매장 가치

- 매장 운영자는 소속이 확인된 매장에서 거래별로 필요한 기능을 활성화한다. 승인된 카페·베이커리는 `픽업 예약`을 `예약만` 또는 `예약+메뉴 홀드`와 병행할 수 있다.
- 매장은 날짜·시간 구간별 전체 예약 가능 인원과 전체 예약 가능 팀 수를 관리하고, 메뉴 홀드를 사용할 때만 게시 메뉴의 제공 구간과 수량을 추가로 관리한다.
- 매장 운영 변경은 이후 신규 거래에 적용하며 기존 확정 거래를 조용히 변경하거나 취소하지 않는다.

## 제품 원칙

- 계정 유형, 로그인 주체와 권한 범위를 분리하고 이메일·휴대전화·외부 로그인 정보의 일치로 권한을 합치지 않는다.
- 공개 탐색과 상태를 만들거나 바꾸는 거래성 경험의 경계를 분명히 한다.
- 중요한 상태 변경은 행위자·근거·대상 매장을 추적할 수 있어야 한다.
- 매장·메뉴 분류, 예약 인원·팀 수와 메뉴 수량은 각각 하나의 뜻만 갖게 한다.
- 뒤 단계 기능과 장기 후보는 현재 범위의 구현 약속으로 해석하지 않는다.

## 성공 판단 기준

일반 사용자는 방문 전에 이용 가능한 운영 모드와 자원을 이해하고 중복·초과 판매 없이 거래를 확정할 수 있어야 한다. 매장 운영자는 자신과 유효하게 연결된 매장에서만 운영 설정과 거래를 관리할 수 있어야 한다. 플랫폼 운영자는 중요한 변경과 예외를 감사 가능한 권한 경계 안에서 처리할 수 있어야 한다.

## 관련 상세 정책

상세 규칙은 [서비스 정책 마스터](service-policies/README.md)를 기준으로 한다. 계정과 인증은 [회원·인증·계정 정책](service-policies/01-member-auth.md), 매장 소속은 [매장 입점·심사·매장 운영자 권한 정책](service-policies/02-store-onboarding.md), 매장·메뉴 분류와 운영 모드는 [매장 운영 정책](service-policies/03-store-operation.md), 예약 자원과 메뉴 홀드는 [예약 정책](service-policies/04-reservation.md)과 [메뉴 홀드 정책](service-policies/06-menu-hold.md)이 소유한다.
