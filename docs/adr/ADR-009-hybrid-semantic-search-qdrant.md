# ADR-009: MySQL 정확 검색 우선과 Qdrant 의미 검색 보완

## 상태

승인 — 2026-08-16, Issue #368

## 맥락

규칙 사전과 MySQL 포함 검색은 날짜·지역 같은 구조화 조건과 등록 메뉴명을 안정적으로 처리하지만 `얼큰한 국물`처럼 등록되지 않은 표현을 `김치찌개`와 연결하지 못한다. 생성형 LLM이 후보나 사실을 직접 만들게 하면 현재 메뉴·매장·예약 상태와 불일치할 수 있다.

## 결정

- `RuleInterpreter`가 날짜·시각·인원과 승인 사전 토큰을 먼저 결정적으로 추출한다.
- MySQL 정확/포함 검색을 항상 먼저 실행한다.
- 잔여 표현은 OpenAI `text-embedding-3-small`로 임베딩하고 Qdrant에서 유사 메뉴 ID를 조회한다.
- Qdrant에는 벡터와 `menuId`, `storeId`, `versionNumber`만 저장하며 MySQL을 원본으로 유지한다.
- 모든 의미 후보는 응답 직전에 MySQL 현재 게시 버전·공개 상태와 Reservation 공개 계약으로 재검증한다.
- 의미 후보는 최초 응답을 채우는 최대 200개 보완 풀로만 사용하며 별도 cursor 페이지를 만들지 않는다.
- 메뉴 변경은 MySQL 커밋 후 비동기로 색인하고, 제한 재시도와 MySQL 기반 전체 백필을 제공한다.
- OpenAI 또는 Qdrant 장애에는 의미 후보를 비우고 정확 검색으로 폴백한다.
- 품절·판매 중단 대체 메뉴는 의미 후보를 우선하되 기존 카테고리·가격·알레르기·재고·예약 검증을 유지한다.

## 결과

의미 검색 품질과 외부 비용·지연을 새로 운영해야 한다. 반면 외부 인덱스가 유실되거나 지연되어도 메뉴 쓰기와 정확 검색은 정상 동작하고, Qdrant는 전체 point 삭제 후 MySQL 원본으로 재구축할 수 있다. 생성형 답변·설명·임의 메뉴 생성은 이 결정의 범위가 아니다.
