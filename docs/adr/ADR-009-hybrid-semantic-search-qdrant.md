# ADR-009: MySQL 정확 검색 우선과 LLM 음식 개념 보완

## 상태

승인 — 2026-08-18, Issue #368

## 맥락

규칙 사전과 MySQL 포함 검색은 날짜·지역 같은 구조화 조건과 등록 메뉴명을 안정적으로 처리하지만 `얼큰한 국물`처럼 등록되지 않은 표현을 `김치찌개`와 연결하지 못한다. 생성형 LLM이 후보나 사실을 직접 만들게 하면 현재 메뉴·매장·예약 상태와 불일치할 수 있다.

## 결정

- `RuleInterpreter`가 날짜·시각·인원과 승인 사전 토큰을 먼저 결정적으로 추출한다.
- MySQL 정확/포함 검색을 항상 먼저 실행한다.
- 정확 검색이 소진된 최초 응답만 OpenAI `gpt-4o-mini` Structured Outputs로 잔여 표현을 최대 8개의 음식 개념으로 해석한다. 특정 입력을 특정 메뉴로 강제 매핑하는 예시는 두지 않고 맛·재료·국물 여부·조리 형태를 종합해 서로 다른 음식 계열의 후보를 다양하게 만들며, `temperature`는 `0`으로 고정해 호출 간 변동을 줄인다.
- 개념은 parameter-bound QueryDSL 포함 조건으로 현재 MySQL 게시 메뉴의 이름·설명·카테고리·태그에 대조한다. 벡터 저장소·외부 색인·검색 캐시는 두지 않는다.
- 모든 보완 후보는 응답 직전에 MySQL 현재 게시 버전·공개 상태와 Reservation 공개 계약으로 재검증한다.
- 보완 후보는 최초 응답을 채우는 최대 200개 풀로만 사용하며 별도 cursor 페이지를 만들지 않는다. 정확 후보와 추천 랭킹 tier가 항상 앞선다.
- OpenAI 비활성·timeout·429·오류·거절·형식 불일치에는 보완 후보를 비우고 정확 검색으로 폴백하며 자동 재시도하지 않는다.
- 품절·판매 중단 대체 메뉴는 공개 메뉴 문맥을 한 번 해석해 같은 매장과 3km 인근 조회에 재사용한다. 같은 주 분류와 가격 ±20%는 하드 필터로 유지하고, 적격 후보는 LLM 개념 50점·보조 분류 20점·가격 유사도 30점의 서버 점수로 정렬한다. LLM 실패 시 개념 점수만 0점으로 두며 일반 후보 폴백과 알레르기·재고·예약 검증을 유지한다.
- 요청에는 최대 500자의 잔여 표현 또는 공개 메뉴 문맥만 포함하고 사용자 ID·연락처·이력·정밀 위치·알레르기 정보는 전달하지 않는다. Secret은 환경 Secret으로만 주입한다.

## 결과

외부 해석의 비용·지연·품질을 운영해야 하므로 호출 수·결과·지연·입출력 토큰을 목적별로 계측한다. 정확 검색이 먼저 페이지를 채우는 대부분의 요청과 cursor 페이지에는 비용이 발생하지 않는다. 외부 장애에도 메뉴 쓰기와 정확 검색은 정상 동작한다. LLM의 생성형 답변·설명·임의 메뉴·가용성·안전 판단은 이 결정의 범위가 아니다.
