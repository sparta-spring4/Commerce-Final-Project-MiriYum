# ADR-010: 사업자등록증 비공개 증빙의 접근·보존 경계

- 상태: Accepted
- 결정일: 2026-08-19
- 현재 적용 단계: 고도화
- 소유 정본: `docs/service-policies/17-privacy-security.md`
- 관련 Issue: #344
- 관련 정책: `docs/service-policies/17-privacy-security.md`

## 문맥

사업자등록증은 공개 매장·메뉴 이미지와 달리 입점 심사에 필요한 비공개 증빙이다. 따라서 공개 URL이나 일반 이미지 DTO로 제공하지 않고, 심사 권한·접근 감사·보존·파기 경계를 별도로 가져야 한다.

현재 저장소에는 비공개 암호화 저장과 배정된 심사자만 짧게 접근한다는 안전 기본선이 확정되어 있다. 2026-08-20에 Store·Privacy 소유자가 승인·반려·교체·분쟁 상태의 보존 기간, 접근 권한, 파기 재시도와 관측 경계를 확정했다.

## 결정

| 증빙 상태 | 보존·파기 기준 |
|---|---|
| 미제출 초안 | 마지막 변경 후 30일 보관한다. |
| 교체된 구버전 | 새 파일이 정상 확정된 뒤 7일 보관한다. |
| 승인·반려·철회된 신청 | 최종 결정 후 90일 보관한다. |
| 보완 요청 중 최신 파일 | 보완본 제출 또는 신청 종료까지 보관한다. |
| 이의·재심·분쟁 | 관련 version의 파기를 보류하고 최종 종결 후 180일을 추가 보관한다. |
| 법적 보존 요구 | 요구 종료일까지 보관하고 종료 후 30일 안에 파기한다. |

원본을 삭제한 뒤에도 증빙 해시, 확인한 사업자 정보 스냅샷, 심사 결과, 정책 버전과 감사 기록은 원본과 분리해 보존한다. 법적 보존은 근거 문서, 대상 version, 승인자와 만료일을 기록하고 90일마다 재검토한다. 분쟁과 관계없는 version에는 원래 파기 일정을 유지하며 포괄적·무기한 보존은 허용하지 않는다.

## 확정해야 할 계약

- 원본 파일은 공개 Store/Menu 이미지와 다른 private prefix와 DTO를 사용한다.
- 원본 URL·파일 내용·사업자등록번호·대표자명은 로그, 분석 이벤트, 메시지에 기록하지 않는다.
- 현재 심사 사건에 배정되고 `STORE_ONBOARDING_EVIDENCE_READ` 권한을 가진 심사자 한 명에게만 접근 경로를 발급한다. `SUPER_ADMIN`도 사건 배정 없이는 접근할 수 없다.
- 접근 경로는 현재 비밀번호 재인증 뒤 발급하는 5분 일회 권한이며, 심사 사건·신청·증빙 ID·version·운영자 세션에 결속한다. 재배정, 권한 회수, 자료 교체 또는 사건 종료 시 즉시 무효화한다.
- 접근 권한 발급과 조회·다운로드의 성공·거절·만료는 대상 신청, 목적, 행위자, 시각과 결과를 감사 이력으로 남긴다.
- 승인·거절·보완·입점 종료와 파일 교체는 메타데이터 상태 전이로 기록한다. 파기 시작 시 `DELETE_PENDING`으로 전환해 모든 접근을 차단하고 실제 객체 삭제를 확인하기 전에는 `DELETED`로 표시하지 않는다.
- 첫 삭제는 즉시 시도하고 실패하면 5분, 30분, 2시간, 12시간, 24시간 뒤 재시도한다. 이후에는 성공할 때까지 하루 한 번 재시도한다. 24시간 이상 미삭제는 운영 경보, 30일 이상은 개인정보 담당자의 수동 조치 사건으로 연결한다.
- S3 `NotFound`는 멱등 삭제 성공으로 처리한다. 객체 삭제 성공 뒤 DB 반영이 실패하면 대사 작업으로 상태를 복구하고, 교체 전 파일 삭제 실패 시에도 새 파일은 사용하게 하되 구파일은 즉시 접근 불가로 격리한다.
- 백업·복제본·복원 환경에도 파기 원장을 전파하며, 일부 실패를 완료로 표시하지 않는다.
- 사업자등록증 기능은 S3 runtime·권한·staging 검증이 완료되기 전까지 활성화하지 않는다.

## 대안

- 심사 완료 후 즉시 파기: 개인정보 보유를 최소화하지만 재심사·분쟁 대응 자료가 부족할 수 있다.
- 매장 생애주기 동안 보존: 운영 확인은 쉽지만 개인정보 보유 기간이 길어진다.
- 심사 완료 후 제한 기간 보존: 최소 보유와 재심사 대응의 균형을 검토할 수 있다.

## 범위

이 ADR은 보존·접근·파기 정책을 확정한다. 실제 private S3 prefix, IAM, 환경 변수, 업로드 API, 공개 Service/DTO, 심사 화면과 staging smoke test는 #344의 후속 구현 PR에서 별도로 다룬다. `#277`은 #344가 제공하는 공개 Service/DTO만 사용하고 File·Store·Auth Entity/Repository를 직접 참조하지 않는다.

## 관측 신호와 재검토 조건

- 접근 경로 발급·조회·다운로드·파기 원장은 대상 신청, 목적, 행위자, 시각, 결과를 남기되 원본 파일 내용과 사업자등록번호를 기록하지 않는다.
- 파기 원장과 객체 상태가 불일치하거나 접근 감사 기록이 누락되면 기능 활성화를 중단하고 재검토한다.
- 파기 재시도가 24시간 또는 30일 경계를 넘으면 운영 경보와 수동 조치 사건이 각각 생성되는지 확인한다.

## 검증 방법

- 문서 검증: `17-privacy-security.md`와 `02-store-onboarding.md`의 보존·접근 경계를 이 ADR과 대조한다.
- 구현 전 검증: private 저장 경로, 공개 이미지 DTO와의 분리, 접근 감사 필드, 멱등 파기와 재시도 계약을 별도 구현 PR의 인수 조건으로 확인한다.
- 운영 검증: 정책 승인과 구현이 끝난 뒤에만 비공개 접근, 만료 경로, 파기 성공·재시도·실패 관측을 staging에서 확인한다.

## 마이그레이션과 되돌리기

- 현재 PR에서는 데이터·스키마·S3·IAM·환경 변수·runtime 활성화를 변경하지 않는다.
- 이 문서 자체는 데이터·스키마·S3·IAM·환경 변수·runtime 활성화를 변경하지 않는다. 구현 PR은 현재 `dev`의 최신 migration 번호를 다시 확인하고 충돌이 없을 때만 번호를 확정한다.
