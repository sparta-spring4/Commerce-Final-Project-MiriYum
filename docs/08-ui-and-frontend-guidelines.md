# 08. UI 및 프론트엔드 가이드라인

## 기본 기술과 경계

프런트엔드는 React 19.2.8, TypeScript 7.0.2, Vite 8.1.5를 사용한다. 화면과 코드는 기능 중심으로 구성하고 화면, UI 상태, API 연동과 입력 검증을 해당 기능이 함께 소유한다. API 호출과 토큰 처리를 렌더링 코드에 흩어 두지 않는다.

## 계정별 shell과 인증 경계

일반 사용자, 매장 운영자와 플랫폼 운영자는 분리된 로그인 시작점·shell·라우트 가드·principal·토큰 namespace를 사용한다.

- 일반 사용자 shell은 탐색·예약·마이페이지를 소유한다.
- 매장 운영자 shell은 서버가 현재 운영자의 관리 권한을 확인한 매장을 선택한 뒤 해당 매장의 설정·거래만 보여 준다.
- 플랫폼 운영자 shell은 `고도화`에서 승인된 심사·지원·감사 기능만 제공한다.

한 shell에서 입력한 역할 값, 이메일 일치나 외부 로그인 결과로 다른 shell의 권한을 열지 않는다. 서버가 반환한 현재 계정 유형·권한과 관리 가능 매장을 기준으로 라우트를 허용하고, 교차 namespace 토큰은 로그인 전환 안내 뒤 거부한다. 세 shell은 한 Vite 앱 안에 있을 수 있지만 UI 편의상 인증 상태나 권한을 합치지 않는다.

Access JWT는 로그인·재발급 응답에서 받아 shell별 메모리에만 보관하고 보호 API의 `Authorization: Bearer` 헤더에 사용한다. Refresh JWT는 JavaScript로 읽거나 Web Storage에 복사하지 않고 namespace별 `HttpOnly` 쿠키로만 다룬다. 페이지 새로고침 뒤에는 같은 계정 shell의 재발급 요청으로 Access JWT를 복구하며, 로그아웃은 메모리 상태와 해당 namespace 쿠키를 함께 제거한다.

## 공통 화면 상태

모든 비동기 화면은 `초기`, `로딩`, `빈 상태`, `성공`, `검증 오류`, `권한 없음`, `충돌`, `결과 불명`, `재시도 가능`, `복구 대기`를 필요한 범위에서 구분한다.

- 중간 선점·결제 처리·전달 시도를 확정 결과처럼 표시하지 않는다.
- 재시도는 같은 멱등 키를 유지해야 하는지 새 요청이 필요한지 서버 계약에 따라 구분한다.
- 오래된 검색·추천 화면은 최종 가용성을 보장하지 않음을 표시하고 거래 직전에 서버가 다시 검증한다.
- 오류에는 가능한 다음 행동을 제시하되 권한·개인정보·다른 사용자의 경쟁 상태를 노출하지 않는다.

폼은 제출 전과 서버 응답 후 모두 검증한다. 필수·형식·범위와 필드 오류를 입력 가까이에 표시하고, 서버 오류 코드를 자체 해석해 성공으로 바꾸지 않는다.

## 단계별 화면 노출

### `1차 MVP`

- 일반 사용자·매장 운영자의 계정 유형별 가입·로그인
- 키워드·5개 지역 탐색, 매장·메뉴 정보
- 예약 가능 조회·생성·상태·취소와 세 거래별 운영 모드
- 일반 사용자 기본 프로필·예약 내역
- 매장 운영자 매장·메뉴·예약 자원 관리

카카오 로그인, 지도, 웨이팅, 결제, 알림, 파일 업로드, 플랫폼 운영자 shell, AI와 실시간 UI는 노출하지 않는다. 뒤 단계 버튼·빈 메뉴·가짜 진행 상태도 만들지 않는다.

### `2차 MVP`

- 규칙 해석 결과와 해석하지 못한 조건의 명시적 경고
- 이력 기반 추천의 설명 가능한 이유
- 품절 대안에서 같은 매장을 우선하고, 같은 매장 후보가 없을 때만 원 매장의 검증된 저장 좌표 기준 3km 이내 후보를 표시
- 지도 결과 표시와 매장 운영자의 좌표 확인

사용자 현재 위치를 요청하지 않는다. 지도는 저장된 매장 좌표만 표시하고 추천 요청 중 외부 지도 호출을 전제로 한 로딩 상태를 만들지 않는다. 3km 경계의 후보는 포함하고 3km를 초과한 후보는 표시하지 않는다. 사용자의 명시적 수락 전에는 대안이 원 거래를 바꾼 것처럼 표시하지 않는다.

### `고도화`

- 일반 사용자 카카오 로그인과 활성 로그인 관리
- S3 기반 비공개 증빙·공개 이미지 업로드 상태와 실패 대사
- 웨이팅·호출·알림·자동 승계·체크인·노쇼 UI
- SSE 연결·재연결·축소 상태
- PortOne V2 결제·환불·결과 불명·대사 상태
- 매장 운영자 대시보드·통계·설정
- 플랫폼 운영자 심사·지원·감사
- 결제·환불·알림·웨이팅 이력

SSE가 끊기면 마지막 표시를 성공 근거로 사용하지 않고 HTTP 재조회로 최신 상태에 수렴한다. PortOne 브라우저 성공 응답은 `확인 중`으로 표시하고 서버 검증 전 `결제 완료`로 표시하지 않는다.

### `향후 고도화`

AI 설명, 구독, 채팅, 리뷰와 추가 관리 기능은 승인된 기능 계약이 생긴 뒤에만 노출한다. AI 설명은 결정적 코드가 확정한 TOP3를 바꾸지 않으며 실패·시간 초과·형식 오류에는 템플릿 설명을 표시한다. 현재 단계 UI에 준비 중 버튼이나 권한을 미리 두지 않는다.

## 접근성·개인정보·보안

- 의미에 맞는 HTML과 레이블을 사용하고 키보드로 주요 흐름을 조작할 수 있게 한다.
- 포커스를 보이고 예측 가능하게 이동시키며 상태 변화·오류를 보조기술에 전달한다.
- 색상만으로 정보·오류·예약 상태를 표현하지 않는다.
- 기본 화면은 마스킹된 최소 정보만 보여 준다.
- 사업자등록증 원본 URL, 토큰, 비밀, 결제수단 원문과 사용자 위치를 클라이언트 로그·분석에 남기지 않는다.
- 플랫폼 운영자의 원문 조회·내보내기는 별도 권한·사건·감사 경계를 통과한다.

## 프런트엔드 검증 gate

- Vitest와 React Testing Library로 상태·폼·라우트 가드·접근성을 검증한다.
- 계정 shell 간 교차 토큰·직접 URL 접근이 거부되는지 검증한다.
- 각 단계에서 뒤 단계 UI·SDK·환경변수·라우트가 노출되지 않는지 검증한다.
- 2차 규칙 경고·추천 설명·지도 기준점, 고도화 SSE 재연결·결제 결과 불명·파일 실패 상태를 컴포넌트와 연동 테스트로 고정한다.
- 실제 실행 파일이나 제공자 sandbox가 없으면 성공했다고 표시하지 않고 검증 상태와 근거를 남긴다.
