# 02. 사용자와 권한

## 핵심 참여자

- 일반 사용자는 매장과 메뉴를 탐색하고 로그인 후 자신의 예약·메뉴 홀드·픽업 등 방문 경험을 관리한다.
- 매장 운영자는 사업자 검증과 매장 소속 확인을 마친 뒤 자신에게 연결된 매장의 운영 자원만 관리한다.
- 플랫폼 운영자는 `고도화`에서 입점 증빙·제한 기능 심사, 고객지원·분쟁, 결제 예외, 장애와 어뷰징 대응을 맡는다. `1차 MVP` 정상 입점은 플랫폼 운영자 권한 없이 자동 확인한다.

## 물리적 계정 분리

세 계정 유형은 하나의 사용자 테이블과 역할 열로 합치지 않는다. 각 유형은 별도 테이블, 별도 기본 키, 별도 인증 주체와 별도 토큰 네임스페이스를 가진다.

| 계정 유형 | 물리 테이블 | 기본 키 | 인증 주체 | 토큰 네임스페이스 |
|---|---|---|---|---|
| 일반 사용자 | `consumer_accounts` | `consumer_account_id` | `consumer:{consumer_account_id}` | `consumer` |
| 매장 운영자 | `store_operator_accounts` | `store_operator_account_id` | `store-operator:{store_operator_account_id}` | `store-operator` |
| 플랫폼 운영자 | `platform_operator_accounts` | `platform_operator_account_id` | `platform-operator:{platform_operator_account_id}` | `platform-operator` |

- 한 사람이 여러 계정 유형을 각각 보유할 수 있지만 기본 키, 로그인 상태, 토큰과 권한은 공유하지 않는다.
- 같은 이메일·휴대전화가 서로 다른 계정 유형에 존재할 수 있다. 이메일 일치, 휴대전화 일치, 외부 로그인 성공이나 로그인 수단 연결은 계정 유형·인증 주체·권한을 생성, 병합, 전환 또는 승격하지 않는다.
- 매장 운영자 계정은 개인별 계정이다. 직원용 계정, 매장 공용 계정이나 다른 계정 유형의 인증정보 공유로 대체하지 않는다.

## 매장 운영자와 매장 소속

매장 운영자와 매장은 명시적인 `store_operator_store_affiliations` 관계로 연결한다. 한 매장 운영자는 여러 매장과 연결될 수 있고, 관계에는 대상 계정·대상 매장·유효 상태·유효 시작·종료 시각과 권한 버전을 둔다.

모든 매장 관리 요청은 다음 네 조건을 함께 검증한다.

1. 요청의 인증 주체가 `store-operator` 네임스페이스의 유효한 매장 운영자 계정인지
2. 매장 운영자 계정 상태가 활성인지
3. 대상 매장과의 소속 관계가 현재 유효한지
4. 대상 매장의 입점 승인·운영 상태가 요청한 기능을 허용하는지

하나라도 확인할 수 없거나 유효하지 않으면 실패 폐쇄한다. 클라이언트가 보낸 계정 유형, 오래된 캐시나 다른 매장의 소속으로 이 검증을 우회하지 않는다.

## 역할별 권한 경계

- 비회원은 공개된 매장·메뉴·가격·예약 가능 여부를 탐색하고 조회할 수 있지만 거래 상태를 만들거나 변경할 수 없다.
- 일반 사용자는 자신의 거래만 관리하며 다른 일반 사용자, 매장이나 플랫폼 운영 영역을 관리할 수 없다.
- 매장 운영자는 유효한 소속이 있는 매장에 한해 등록·운영 설정과 예약·메뉴 홀드·픽업 자원을 관리한다. 일반 사용자 계정이나 다른 매장·플랫폼 운영 영역을 대신 관리할 수 없다.
- 플랫폼 운영자는 `고도화`에서 부여된 업무 권한 안의 심사, 분쟁, 수동 복구와 장애 대응을 수행한다. 민감한 접근과 대량 작업은 업무 범위·승인·감사 경계를 따른다.

## 단계별 인증 경계

- `1차 MVP`는 세 계정 유형마다 별도 네임스페이스로 발급한 stateless Access JWT와 Refresh JWT를 사용하며 서버에 정상 토큰이나 리프레시 상태를 저장하지 않는다.
- `고도화`에서 Valkey 기반 Refresh Token 회전·폐기·재사용 탐지와 일반 사용자 카카오 로그인을 도입한다.
- 단계가 바뀌어도 계정의 물리적 분리와 이메일·외부 로그인에 의한 권한 불변 원칙은 유지한다.

## 상세 정책 연결

가입, 로그인, 토큰, 복구와 계정 제재는 [회원·인증·계정 정책](service-policies/01-member-auth.md)에서 정한다. 매장 등록과 소속 확인은 [매장 입점·심사·매장 운영자 권한 정책](service-policies/02-store-onboarding.md), 플랫폼 운영자 심사·분쟁·수동 복구는 [플랫폼 운영자·분쟁·수동 복구 정책](service-policies/15-admin-operation.md), 개인정보와 민감 정보 접근 경계는 [개인정보·보안 정책](service-policies/17-privacy-security.md)에서 정한다.
