# 문서 변경 이력과 카페·베이커리 단독 픽업 홀드 정합성 설계

## 목표

문서 수정의 결정자·작업자·시점·대상·내용·이유를 중앙 이력에서 한눈에 확인할 수 있게 하고, `HOLD-005` 단독 픽업 홀드를 예약 시스템 내부의 카페·베이커리 전용 예외로 정렬한다.

## 중앙 변경 이력

새 영구 작업 일지나 수명 주기 문서를 만들지 않는다. 기존 중앙 역사 기록인 `miriyum-service-decisions.md`가 문서 변경 이력도 소유한다.

2026-07-24 이후 새 기록은 가로로 긴 표 대신 날짜별 카드 형식을 사용한다.

```markdown
### DOC-YYYYMMDD-NNN · 변경 제목

- 변경 일시: `YYYY-MM-DD HH:mm KST`
- 요청·결정자: 이병우
- 수정 작업자: 실제 문서 수정자
- 대상 문서·정책: 변경한 정본과 정책 ID
- 변경 내용: 이전 기준과 새 기준이 드러나는 요약
- 변경 이유: 제품·정책·정합성 관점의 근거
- 추적 정보: 관련 PR과 커밋
```

과거 누적 표와 날짜별 정책 결정은 역사로 보존한다. 새 카드가 현재 정본을 대신하지 않으며, 정책 의미는 관련 `docs/` 정본이 계속 소유한다. GitHub Project 상태나 테스트 실행 결과를 중앙 이력에 복제하지 않는다.

`docs/00-index.md`, `docs/service-policies/README.md`, `docs/service-policies/00-policy-template.md`에는 다음 운영 규칙만 연결한다.

- 정본 문서를 수정하면 중앙 변경 이력 카드를 함께 갱신한다.
- 정책 문서의 `결정 기록`은 정책 ID별 의미·상태·근거를 기록한다.
- 중앙 변경 이력은 실제 문서 수정의 요청·결정자, 작업자, 대상, 내용과 이유를 기록한다.
- PR·커밋은 추적 링크이며 현재 정책의 단일 원본이 아니다.

이번 변경에서는 요청·결정자를 `이병우`, 수정 작업자를 `Codex`로 기록한다.

## 단독 픽업 홀드 적용 범위

`HOLD-005`는 `booking`이 소유하는 예약 시스템 내부의 업종별 예외 흐름이다.

- 카페와 베이커리는 홀 운영 여부와 관계없이 단독 픽업 홀드를 활성화할 수 있다.
- 홀을 운영하는 카페·베이커리도 테이크아웃 요청에는 단독 픽업 홀드를 사용할 수 있다.
- 같은 매장의 방문 예약 요청에는 `HOLD-004`의 예약 수용량·메뉴 수량 결합 선점을 적용한다.
- 일반 식당과 다른 업종에는 단독 픽업 홀드를 제공하지 않는다.
- 적용 이유는 카페·베이커리에 홀 없이 테이크아웃 중심으로 운영하는 매장이 많아 방문 예약 수용량 없이 메뉴와 픽업 시간만 관리하는 흐름이 필요하기 때문이다. 홀 없는 매장만 허용한다는 조건은 아니다.

## 예약 시스템 내부 책임

단독 픽업 홀드는 방문 예약 레코드나 좌석·인원 수용량을 만들지 않지만 별도 도메인으로 분리하지 않는다.

- `booking`이 사용자 자격, 메뉴 수량, 픽업 제공 구간, 임시 선점, 확정, 변경, 취소, 만료와 수령 상태를 관리한다.
- 예약 연계 홀드와 단독 픽업 홀드는 같은 메뉴 수량 원장, 멱등성, 만료, 취소 복구, 품절, 대체 메뉴, 대기 승계와 감사 규칙을 공유한다.
- 단독 픽업 홀드는 메뉴 수량과 픽업 제공 구간만 선점하고 방문 예약 수용량은 선점하지 않는다.
- 사용자 흐름에서는 카페·베이커리 테이크아웃 요청을 별도 시작 조건으로 보이되, 정책과 도메인 소유권은 `booking`으로 연결한다.

## 문서별 정렬

- `docs/03-domain-model.md`: `booking`이 카페·베이커리 단독 픽업 예외를 함께 소유함을 명시한다.
- `docs/04-user-flows.md`: 카페·베이커리 단독 픽업 홀드 흐름을 추가한다.
- `docs/05-functional-requirements.md`: 메뉴 홀드의 업종별 예외를 카페·베이커리 전용으로 요약한다.
- `docs/service-policies/02-store-onboarding.md`: 베이커리만 허용하고 방문 예약 개념이 없다고 단정한 문구를 교체한다.
- `docs/service-policies/06-menu-hold.md`: 모든 식당이 활성화할 수 있거나 예약 시스템과 완전히 독립된 것처럼 보이는 문구를 제거하고 `HOLD-005`의 자격·흐름·인수 조건·결정 기록을 갱신한다.
- `miriyum-service-decisions.md`: 이 결정과 실제 문서 변경을 새 카드 형식으로 기록한다.

## 검증 기준

- 단독 픽업 홀드를 베이커리만 허용하거나 모든 식당이 허용하는 현재 문구가 없다.
- 카페·베이커리의 홀 운영 여부가 단독 픽업 홀드 자격 조건으로 사용되지 않는다.
- 일반 식당과 다른 업종은 단독 픽업 홀드를 활성화할 수 없다.
- 단독 픽업 홀드는 `booking` 내부 흐름이며 방문 예약 수용량만 만들지 않는다는 경계가 일치한다.
- 중앙 변경 이력의 새 기록에 `이병우`, `Codex`, 변경 일시, 대상, 내용, 이유, 추적 정보가 모두 있다.
- 과거 결정 기록과 현재 정본의 역할이 뒤바뀌지 않는다.
- 상대 링크, UTF-8, BOM, 끝 개행과 `git diff --check`가 통과한다.
